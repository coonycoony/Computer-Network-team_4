Static Router 사용법 (Router II 버전)
=====================================

실행 파일
---------
  Router II (현재 코드)  : x64\Release\ipc2019.exe
  Router I  (보고서용)   : Router1_backup\x64\Release\ipc2019.exe

  두 버전의 사용법은 같습니다. 다른 점은 맨 아래 "Router I 버전과 다른 점"을 보세요.


1. 사전 준비 (라우터 PC)
------------------------
  1) Npcap 설치 (npcap.com)
  2) 유선 랜카드 2개 연결 (USB 랜카드 가능, Wi-Fi 불가)
  3) 두 랜카드 모두 TCP/IPv4 체크 해제
       제어판 > 네트워크 연결 > 어댑터 우클릭 > 속성
       > "인터넷 프로토콜 버전 4(TCP/IPv4)" 체크 해제 > 확인
  4) 랜선 연결
       내부 Network 랜카드 (Port1) : Host A
       외부 Network 랜카드 (Port2) : Cisco GE 0/0  (Router I 구성에서는 Host B)
       Cisco GE 0/1               : Host B


2. 호스트 설정
--------------
  예제 주소 기준입니다. 데모에서는 당일 확인한 주소를 사용합니다.

  Host A : IP 192.168.1.2 / Mask 255.255.255.0 / Gateway 192.168.1.1
  Host B : IP 172.16.0.2  / Mask 255.255.255.0 / Gateway 172.16.0.1

  Windows 호스트는 관리자 권한 cmd에서 ICMP 허용 규칙을 추가합니다.
  (다른 네트워크에서 온 ping은 기본 규칙으로 차단됩니다.)

    netsh advfirewall firewall add rule name="ICMP Allow" protocol=icmpv4:8,any dir=in action=allow remoteip=any


3. Cisco 설정 확인 (콘솔)
-------------------------
  PuTTY > Connection type: Serial, Serial line: COM 번호, Speed: 9600
  접속 후 Enter를 누르고 아래 명령을 입력합니다.

    show ip interface brief
    show ip route

  show ip route 에서 읽을 것 (예제)
    S 192.168.1.0/24 via 10.0.0.2     -> Port2 IP = 10.0.0.2
    L 10.0.0.1/32 (Gi0/0)             -> UG 엔트리의 Gateway = 10.0.0.1
    C 172.16.0.0/24 (Gi0/1)           -> UG 엔트리의 Destination = 172.16.0.0
  Port1 IP는 Host A의 Default Gateway와 같아야 합니다 (Host A에서 ipconfig).
  /24 같은 Prefix 길이는 Netmask로 바꿔 입력합니다 (/24 = 255.255.255.0, /26 = 255.255.255.192).


4. 프로그램 설정
----------------
  1) ipc2019.exe 실행
  2) 내부 Network : Host A 쪽 랜카드 선택, 인터페이스 IP 입력 (예: 192.168.1.1)
     외부 Network : Cisco 쪽 랜카드 선택, 인터페이스 IP 입력 (예: 10.0.0.2)
       - 어댑터 옆에 표시되는 MAC을 실제 랜카드 MAC과 비교하세요 (cmd: getmac /v).
       - 내부/외부를 반대로 고르면 라우터까지도 ping이 안 됩니다.
  3) Static Routing Table 아래 Add 버튼으로 엔트리를 입력합니다.

       Destination   Netmask         Gateway    Flag          Interface
       192.168.1.0   255.255.255.0   (비움)     UP            Port1
       10.0.0.0      255.255.255.0   (비움)     UP            Port2
       172.16.0.0    255.255.255.0   10.0.0.1   UP, Gateway   Port2

       - 직접 연결된 네트워크는 UP만 체크하고 Gateway는 비웁니다.
       - Cisco 너머의 네트워크는 UP과 Gateway를 체크하고, Gateway에 Cisco Gi0/0의 IP를,
         Interface에 Gateway가 있는 쪽 포트(Port2)를 고릅니다.
       - Cisco에 C 엔트리가 더 있으면 (Gi0/0 쪽 제외) 각각 UG 엔트리를 추가합니다.
       - 기본 경로는 Destination 0.0.0.0, Netmask 0.0.0.0 으로 입력합니다.
       - Host 플래그를 체크하면 Netmask가 255.255.255.255로 채워집니다.
       - 같은 Destination/Netmask를 다시 Add하면 기존 엔트리를 덮어씁니다.
  4) Start 버튼을 누릅니다.
       - 실행 중에도 Routing Table의 Add / Delete가 가능합니다.
       - End를 누르면 정지하며, Routing Table과 Proxy ARP Table은 유지되고 ARP Cache는 지워집니다.
       - 어댑터와 인터페이스 IP는 정지 상태에서만 바꿀 수 있습니다.


5. 테스트 순서
--------------
  가까운 구간부터 차례로 확인합니다.

  #  위치         명령               확인하는 구간
  1  Host B       ping 172.16.0.1    Host B - Cisco
  2  Host A       ping 192.168.1.1   Host A - 구현 라우터 Port1
  3  Cisco 콘솔   ping 10.0.0.2      Cisco - 구현 라우터 Port2
  4  Host A       ping 10.0.0.1      구현 라우터를 지나 Cisco까지
  5  Host A       ping 172.16.0.2    종단
  6  Host B       ping 192.168.1.2   역방향 종단

  5, 6번의 응답 TTL은 Windows 호스트 126, macOS 호스트 62 입니다 (라우터 2개 통과).


6. 화면 설명
------------
  Static Routing Table : 입력한 엔트리 (Flag U = 직접 연결, UG = Gateway 경유, H = Host)
  ARP Cache Table      : 포트별로 알아낸 IP - MAC. Delete로 선택 항목 삭제.
                         정상 동작 시 Cisco Gi0/0(10.0.0.1)과 Host A(192.168.1.2)가 보이고,
                         Host B(172.16.0.2)는 보이지 않습니다 (다른 네트워크라 ARP 대상이 아님).
  통계                 : IP 수신 / 전달 / 경로 없음 / TTL 만료, ARP Request / Reply / 실패, Ping 응답
                         "최근" 줄에 마지막으로 처리한 패킷의 입출력 포트와 처리 결과가 표시됩니다.
  Proxy ARP Table      : 등록한 IP에 대한 ARP Request에 라우터가 대신 응답 (이번 과제에서는 사용하지 않음)
  맨 아래 줄           : 안내 및 오류 메시지


7. 안 될 때
-----------
  - Start가 안 눌림            : 유선 어댑터가 2개 미만이거나 Npcap 미설치
  - "Windows IPv4 사용 중" 표시 : 해당 랜카드의 TCP/IPv4 체크 해제
  - 2번 ping 실패              : 내부/외부 어댑터 선택이 반대이거나 Port1 IP가 Host A의 Gateway와 다름
  - 3번 ping 실패              : Port2 IP가 Cisco S 엔트리의 Next hop과 다르거나 GE 0/0, GE 0/1을 바꿔 꽂음
  - 5번만 실패, "경로 없음" 증가 : UG 엔트리 누락 또는 Destination/Netmask 오타
  - "next hop ... ARP 응답이 없습니다" : Gateway IP 또는 Interface 선택 오류, 랜선 확인
  - 한쪽 방향만 됨             : 호스트 방화벽 (2번 항목의 ICMP 허용 규칙)
  - 그래도 안 되면 Wireshark로 ICMP가 어느 구간까지 가는지 확인


Router I 버전과 다른 점 (보고서용)
----------------------------------
  - 구성 : Host A - 구현 라우터 - Host B (Cisco 없음, 3번 항목 생략)
           Host B 예: IP 10.0.0.1 / Mask 255.255.255.0 / Gateway 10.0.0.2
  - Routing Table : UP 엔트리 2개만 입력 (192.168.1.0 -> Port 0, 10.0.0.0 -> Port 1)
  - 포트 이름이 Port 0 / Port 1 로 표시됩니다.
  - 라우터 자신의 IP로 보낸 ping에는 응답하지 않습니다 ("요청 시간 만료"가 정상).
    Host A <-> Host B 종단 ping으로 확인하며, 응답 TTL은 127 입니다.
